# 0016 — One Docker Compose stack: Oracle primary, Jetson home backup
Date: 2026-10-04 · Status: accepted (revised the same day once our hardware was known)

**Context:** We self-host for free. Our home hardware is a **Raspberry Pi 3 Model B (1 GB)** and an **original Jetson Nano (4 GB, JetPack 4.6, GPU not usable by current LLM runtimes)**, both on SD cards. Oracle Always Free gives 2 Ampere OCPU / 12 GB (cut from 4/24 in June 2026). Our domain is on Cloudflare.
**Decision:** The app runs with **docker compose** (cloudflared, Caddy, FastAPI api + worker, Postgres, Ollama), identical on every host; only `.env` differs. **Oracle = primary** (the only machine that can run the vision model). **Jetson Nano = home backup target + cold standby** (pulls encrypted nightly restic backups; can run the stack without the model). **Pi 3 = optional Uptime Kuma monitor.** Public access via **Cloudflare Tunnel** on our domain (no open ingress ports). All hosts are ARM64 → `linux/arm64` images on GHCR.
**Alternatives:** Home-first on Pi/Jetson (rejected: 1 GB Pi can't run the stack; Jetson's GPU is unusable for LLMs, its CPU is slow and SD cards wear under Postgres writes); paid VPS (rejected: zero cost, 0019).
**Consequences:** Data lives on Oracle, with a full copy at home. Oracle may change terms or reclaim idle instances; mitigated by a resident model (memory above the idle threshold), home backups, and a tested failover. Restore drill once per phase.
